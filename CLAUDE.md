# Viable System Explorer: notes for Claude

An interactive explorer for Stafford Beer's Viable System Model (VSM). The user, Panos (Close the Loop), teaches the VSM (OCAD University) and uses it in consulting. The README describes what the app does; this file holds what a new session needs to keep working the same way.

## Shape of the code

- The app is one file, `index.html` (about 6,100 lines): CSS, markup, then one classic `<script>`. three.js r128 and OrbitControls load from `vendor/three/` (committed, MIT licence) with cdn.jsdelivr as the fallback (an inline `<script data-fallback>`; keep it attributed so the plain-`<script>` syntax check below still finds the main script); fonts come from Google Fonts. No build step. No build step.
- The script is split by banner comments (`/* ===== … */`). In order: Helpers; Knowledge base (`KB`, what each element and channel is, after Beer); Canonical layout (`buildLayout`, 2D world units reused by 3D); Model data (`db`, levels, `load`/`save`/`normaliseDb`); Data flows (standard flows, the model company `EXAMPLE`, `PRESETS`); Theme; 3D scene (`buildScene`, `updateGeometry`, `refreshVisuals`); Labels overlay; Camera and view transitions (`setView`, `camTween`, `fitState`); Orthogonal (`buildHemi`, `hemiRefresh`, `HG` geometry constants); Picking; Recursion (`dive`, `goToLevel`, zoom-through); Panels; Wiring (event listeners, the Model menu, Claude mapping); Value network (SVG); Export (`offerFile`, `viewPng`/`viewSvg` read the WebGL picture plus the label overlay word by word, `netSvgText` inlines the network's styles, `findingsRows` feeds the CSV and the HTML report); Start, presenting and shortcuts (welcome, About, focus keys, tour, presentation mode); Boot.
- State: `db = { seq, rootId, currentId, scheme, levels }`. Each level has `opCount`, `labels`, `colors`, `groupColors`, `notes`, `flows`, `diag`, `children` (keyed by operation id `o0`…), optional `net` (value network) and `purpose`. Element ids: `o0…` operations, `m0…` local managements, `a0…` local System Two units, `e0…` local environments, `s2 s3 s3s s4 s5`, `env`, `fut`, `meta`, `sys1`. Channel ids are in `buildLayout`.
- `prefs` (view, diagram, theme, conventions) and `db` are saved together in localStorage under `vsm-explorer:v1`. Saved files (`*.vsm.json`, format `viable-system-explorer` v1) carry `model` plus `conventions` (style, s2mode, localS2, extS4cmd, extS14, valueFlows). Old storage must keep loading: add migrations in `load`/`normaliseDb`, never break the format.
- Views: `prefs.diagram` is `vsm | net | rec`; within VSM, `prefs.view` is `2d | 3d | hemi`. The Orthogonal view (`hemi` in code and saved state; renamed from Hemispheres on Nov 20 2026 at Panos's request: it is Beer's orthogonal representation of management on operations, not about brain hemispheres or now versus future) has its own scene (`hscene`/`hroot`) built from clones of the classic elements.

## Design decisions already agreed (do not undo without asking)

- **Orthogonal re-interprets, it does not add.** Shapes are clones of the classic elements with their materials; channels keep the classic widths. Panos rejected an earlier version with "pipes", a rim, a wire dome and extra rods. Nested models sit perpendicular. The future-environment dome stays (faint).
- **System Two in Orthogonal** is a ring through every local management (always drawn, local regulatory centres on or off); its regulatory centre is a smaller ring hugging the central column.
- **System Three-Star in Orthogonal** has no triangle: its audit lines run from System Three straight to each operation, arching past the local managements. 2D/3D keep Beer's triangle.
- **Value flows** (operational linkages `oo`, operation–environment `eo`) are drawn as wide pale ribbons with broad arrowheads in every view, after value-stream maps; cybernetic channels stay thin lines. Settings › Value flows switches to lines. Beer's squiggles were removed on purpose. Environmental intersects (`ee`) have no channel line: since v1.5 (Nov 19, Panos asked for overlap "even symbolically at first") the local environments in 2D/3D are taller, staggered left and right and translucent, so each overlaps its neighbours as in his diagram (Beer's channel iv). Orthogonal does not show overlap yet. Since v1.6 overlap follows `intersect(lv, i, j)`: a pair set by hand (`lv.isect['i-j'] = { on, why }`, kept through `removeOperation` and `normaliseDb`), else shared actors when the value network has any (`netShowsIsect`), else symbolic between neighbours. Channel iv is any intersect, not only shared actors (NotebookLM via Panos, Nov 19), hence the manual setting with a reason. `buildLayout` takes `opts.isect` (neighbour pairs) and shortens each environment towards a neighbour it does not intersect. Non-neighbour intersects are listed in the details but not drawn (Panos, Nov 19: list only for now; reordering and a bridge were both declined for the time being).
- Linkages between operations are representative (each operation to its neighbour), not a copy of every value-network flow. Orthogonal closes the ring.
- Nested models show only when Nested is on.
- Recursion runs only through System One. Level numbers are relative to the level set as L0 (`db.refId`).
- Examples are complete models under the Model menu; each replacement of the model offers Undo.
- Licence (decided Nov 2026): code AGPL-3.0-or-later (`LICENSE`), own text and examples CC BY-SA 4.0, name and logo reserved. No sign-in gate. About dialog holds version (`APP_VERSION`), licences and citation; bump the version there when releasing.
- **Brand (Nov 19 2026):** the app wears Close the Loop's brand (skill `close-the-loop-design` in `pan0sp/skills`): navy `#141b38`, gold `#eeba2b` (gold text on light is `#a07a0e`), off-white; Raleway display, Open Sans body, Comfortaa only for the wordmark (Panos agreed: too wide for small UI text); IBM Plex Mono stays for codes. Light is the default theme when none was chosen (`prefs.themeChosen`). The app mark is E-O-M (Environment, Operations, Management): nested in the toolbar, opening out with double arrows in the About pop-up beside the vector Close the Loop C mark. No gradient backgrounds (brand rule). Dark theme (Nov 20, v1.6.1, Panos chose black over navy and charcoal): the stage is pure black so the model stands out, panels are neutral near-black; navy stays only in the brand panels (About, welcome).
- First visit opens in 2D with panels closed and the welcome card (three entry choices). Keys: `1`–`5`, `*`, `E` (twice: future), `M`, `A`, `0` focus systems; `D` toggles 2D/3D (no longer `2`/`3`); `PageUp`/`PageDown` tour; `P` presentation mode (dark, full screen, caption, larger labels; Esc leaves at once); `?` shortcut sheet. Toolbar groups: views, layers, present plus a ⋯ menu (theme, shortcuts, start screen, about).
- Laws: where Wikipedia's "Viable system model" article states a law (the four principles, three axioms, law of cohesion, recursive system theorem), its wording is quoted exactly (`wiki: true`, credited in the Laws card and About, CC BY-SA 4.0; Panos asked for this Nov 19). Requisite variety and the good regulator theorem are not stated there, so they stay paraphrased and say so. Do not add a law without a source. Welcome card states the positioning: a tool for the facilitated diagnosis of real organizations, not only to learn the VSM (Astra, Nov 19: keep "facilitated" until the evidence workflow is strong).
- Framing (`fitState`, `hemiFit`) keeps the model clear of the Method card, level chip, hint bar and caption via `stageCover()`.

## Checks

```
npm install          # three@0.128.0, served to the page in place of the CDN
npm test             # runs every check in tests/, or: node tests/run.js hemi
```

The checks drive the real page with Playwright (not listed in package.json, because the cloud containers ship their own Chromium and Playwright and a second copy breaks them). On your own machine run `npm i --no-save playwright && npx playwright install chromium` once. Each check prints `ok`/`FAIL` lines and the page errors; a failed font load is expected (fonts are blocked). Screenshots land in `tests/.out/shots/`. `node --check` cannot parse the HTML; for a quick syntax check extract the script: `node -e "const s=require('fs').readFileSync('index.html','utf8');new Function(s.match(/<script>([\s\S]*)<\/script>/)[1])"`.

Look at screenshots after visual changes: most regressions here are visual.
